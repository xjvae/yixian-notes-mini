## 三、优先级汇总

**P0（建议尽快做，共 1 项）**

- A-1 建立 CI：现成的 `npm run verify` 六道门禁直接接上 GitHub Actions 即可，边际成本最低、收益最大。

**P1（下个迭代窗口，共 7 项）**

- B-1 内容明文 Zeroizing；B-2 capabilities 按 label 收窄；C-1 拆分 private_note.rs；D-1 拆分 note-content.tsx；D-2 group-stack 按成员订阅；D-3 ring 订阅失败补日志；D-4 两处锁 poison 对齐硬规。

**P2（择机打磨，共 11 项）**

- A-2 dependabot；A-3 unlock/settings 组件测试；A-4 ARCHITECTURE.md 入库；A-5 留底文件归档；B-4 textContent；D-5 丢事件计数；D-6 搜索 stale-response 守卫；D-7 托盘图标降级；D-8 一致性清理；F-1 依赖升级；C-2 MenuAction 类型下沉。

## 四、结语

本代码库的安全设计（私密层八域 AAD、双层链接白名单、CSP 不放远程图）与工程纪律（分层 eslint 强制、mirrored-constants 编译期围栏、计时器清理零遗漏）达到了商业产品水准，文档-代码同步度在个人项目中罕见。最值得投入的下一步是**把已有的手工质量门禁自动化**（P0 的 CI），其余中危项均为"把已经很高的标准拉齐到自家纪律"性质，无一处需要伤筋动骨。
